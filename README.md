# Feishu Wiki Sync

将 Obsidian 仓库中的 Markdown 笔记与飞书知识库双向同步。当前维护版 **0.1.1**，基于已可用的 `v0.1.0` 修复整理；已有标签不变。

仅支持 **Obsidian 桌面版 1.4.0 及以上**，连接中国版飞书（`open.feishu.cn`）。当前不包含 Notion、飞书多维表格或国际版 Lark 接入，也没有发布到 Obsidian 社区插件市场。

## 选择同步模式

| 模式 | 飞书中保存的内容 | 适合用途 | 边界 |
| --- | --- | --- | --- |
| 文档模式 | 可阅读、可编辑的飞书新版文档 | 在 Obsidian 写作，在飞书阅读和协作 | 会转换排版，不保证 Markdown 源码逐字不变 |
| 文件镜像（默认） | 原始 `.md` 文件 | 保留原始 Markdown 内容 | 不上传附件，飞书侧的展示取决于 Markdown 文件预览 |

两种模式都支持预览、双向同步、单向推送/拉取和冲突副本。只同步 `.md` 笔记；文档模式会另行处理笔记引用的本地图片。

## 安装

### 使用构建好的安装包

1. 解压 `feishu-wiki-sync-0.1.1.zip`，得到 `feishu-wiki-sync` 文件夹。
2. 关闭 Obsidian，将该文件夹放入目标仓库的 `.obsidian/plugins/` 下。最终应为：

   ```text
   你的仓库/
   └── .obsidian/
       └── plugins/
           └── feishu-wiki-sync/
               ├── main.js
               ├── manifest.json
               └── styles.css
   ```

3. 重启 Obsidian，在 **设置 → 第三方插件** 中关闭限制模式，启用 **Feishu Wiki Sync**。
4. 打开该插件的设置，按下文完成飞书授权与同步目标配置。

若已有旧版，只替换以上三个文件，**保留 `data.json` 和 `.obsidian/feishu-sync/`**。它们保存账号授权、同步映射和转换规则。不要用整目录删除再复制的方式升级。

安装布局遵循 [Obsidian 官方插件说明](https://github.com/obsidianmd/obsidian-sample-plugin#manually-installing-the-plugin)。

### 从源码构建

需要 Node.js **20 或以上**及 npm。在本仓库目录运行：

```sh
npm ci
npm run package
```

`package` 依次进行类型检查、全部离线测试、生产构建和打包。成功后输出：

```text
dist/
├── feishu-wiki-sync/
│   ├── main.js
│   ├── manifest.json
│   └── styles.css
├── feishu-wiki-sync-0.1.1.zip
└── SHA256SUMS
```

安装包只包含三个运行文件，不包含源码、测试数据、账号或笔记。`SHA256SUMS` 提供文件和压缩包校验值。只需编译时运行 `npm run build`，输出安装目录并更新仓库根目录的 `main.js`。

也可在关闭 Obsidian 后直接安装到本地仓库：

```sh
npm run install:vault -- "/完整路径/你的仓库"
```

脚本会先构建，再检查仓库是否已有 `.obsidian` 目录，备份原有的三个安装文件到插件目录内的 `.backup-时间戳/`，最后替换文件；账号、映射与规则不变。没有指定路径时直接报错，不会猜测安装位置。也支持通过 `OBSIDIAN_VAULT` 指定仓库；自定义 Obsidian 配置目录可使用 `OBSIDIAN_CONFIG_DIR`（相对仓库路径）。

## 配置飞书应用

### 1. 创建并发布自建应用

在 [飞书开发者后台](https://open.feishu.cn/app) 创建企业自建应用，从“凭证与基础信息”取得 **App ID** 与 **App Secret**。

在“权限管理”中申请下列权限，与插件默认授权范围保持一致：

| 权限标识 | 插件用途 |
| --- | --- |
| `drive:drive` | 文件读写、查询元数据，以及用户开启后的删除传播 |
| `wiki:wiki` | 列出知识空间、读取和创建目录节点、移动文档到知识库 |
| `docx:document` | 文档模式中的创建、读取、编辑文档与图片块 |
| `docs:document.media:download` | 下载文件和文档图片素材 |
| `docs:document.media:upload` | 文档模式上传图片素材 |
| `offline_access` | 用户授权后获取刷新凭证，维持登录 |

使用“用户授权”时，需开通相应的**用户身份权限**；使用“应用身份”时，需开通相应的应用身份权限，且无需 `offline_access`。后台若提示管理员审批，完成审批后再继续。上述是本插件默认使用的权限集合，不是按单一功能裁剪的最小权限集合。

在应用的安全设置中登记重定向 URL，默认值必须逐字一致：

```text
http://localhost:7634/callback
```

在“版本管理与发布”中创建并发布版本，应用可用范围需要包含你自己的飞书账号。之后更改权限或可用范围也需要重新发布；增加用户授权范围后，需要在插件中重新授权。

文档模式的 Markdown 接口与 [飞书官方 CLI 的文档实现](https://github.com/larksuite/cli/tree/main/shortcuts/doc) 保持相同请求格式；插件直接调用 API，**不需要安装 CLI**。

### 2. 在 Obsidian 中授权

进入 **设置 → Feishu Wiki Sync → 飞书应用与授权**：

1. 选择 **用户授权（推荐）**，填写 App ID、App Secret。
2. 保留上述重定向地址及默认“授权范围”。若你调整了后台权限，同步调整范围，两边必须一致。
3. 点击 **授权飞书账号**，在浏览器中选择有权限访问目标知识库的账号并同意授权。
4. 返回 Obsidian，确认授权成功，再点击 **连接测试**。

自动授权会临时启动本机回调服务，最多等待五分钟。若端口被占用，可将插件与飞书后台的回调地址同时改到另一个本机端口。也可以使用 **手动粘贴授权码**：浏览器完成授权后，即使回调页面无法打开，仍可复制地址栏中带 `code` 的完整地址或授权码到插件。

“应用身份”适合已有应用管理配置的团队：需让应用身份拥有目标知识空间及文档的权限。接口权限和知识库内容权限是两件事；开通 API 权限并不自动获得所有文档的访问权。

App Secret 和授权令牌保存在本仓库 `.obsidian/plugins/feishu-wiki-sync/data.json`，未额外加密。不要公开此文件，也不要在多台设备间共用正在刷新的用户令牌。界面的“撤销授权”仅清除本机保存的授权信息。

### 3. 选择同步目标

| 设置 | 填写方式 |
| --- | --- |
| 知识空间 `space_id` | 推荐点击 **拉取列表** 后选择。手填使用知识空间 ID，不能把 `/wiki/节点令牌` 页面链接当作 space_id |
| 同步根节点 | 推荐先在飞书建立一个专用页面，把它的 `/wiki/…` 链接或 node_token 填到这里；只同步其下的内容 |
| 根目录页面标题 | 仅根节点留空时使用；存放仓库根目录散装笔记的页面名称，留空使用仓库名 |
| 笔记同步形态 | 需要在飞书美观阅读与编辑时选 **文档模式**；需要原始源码时选 **文件镜像** |
| 目录层级 | 推荐 **镜像目录**：本地文件夹对应知识库目录页面 |

根节点留空时会扫描整个知识空间：本地一级文件夹成为空间一级页面，根目录笔记放入“根目录页面”；空间顶层已有的笔记也可能被拉回本地。首次使用建议选择专用根节点，先检查预览范围。

切换知识空间、根节点、同步模式或目录编码设置后，会清空旧映射并重新对接。同名内容不一致时保留双方并报告冲突；这不是将原有远端内容自动迁移到新目标。

## 首次同步与日常使用

1. 先选择模式、目标和排除规则，保留 **同步前预览计划** 开启。
2. 打开命令面板，运行 **Feishu Wiki Sync: 预览同步计划**。
3. 检查上传、拉取、删除及冲突分组，确认路径和数量。
4. 点击 **执行全部**，或选择 **仅拉取（不推送）**；查看完成报告。

后续可使用侧栏同步按钮、底部状态栏，或命令面板中的“双向同步”“从飞书拉取到本地”“把本地推送到飞书”。命令中的单向同步仍遵守冲突保护，不代表无条件覆盖。

**强制重推**仅用于文档模式：忽略同步基线，以本地非空笔记覆盖对应远端文档。它可能覆盖飞书独有的内容，始终需要预览确认。正常规则升级会自动生成受保护的刷新计划，一般不需要强制重推。

## 常用设置与转换规则

- **排除规则**：每行一个 glob，支持 `*`、`**`、`?`，`#` 开头为注释。例如 `日记/**` 排除目录，`**/草稿.md` 排除任意层级的同名笔记，包括根目录。`.obsidian/`、`.trash/` 与冲突副本始终排除。
- **附件目录**：默认 `attachments`，必须是仓库内的相对目录。文档模式将可解析的本地图片上传为飞书图片块，远端图片下载至此；图片失败会出现在报告中。
- **附件链接写法**：默认只写文件名，如 `![[image.png]]`；若仓库中常有同名附件，改用带目录形式。
- **定时自动同步**：默认 `0`，表示关闭。填写正整数分钟后，Obsidian 运行且插件启用时才生效；不弹计划预览，冲突仍生成副本，删除操作留待手动同步确认。
- **删除传播**：两项默认关闭。开启后，手动同步会强制显示预览；本地删除可传播到飞书回收站，远端删除可将本地笔记移到 `.trash`。执行前再次校验内容，检查失败则保留文件。
- **每轮取回全文校验**：默认关闭，通常使用远端修改时间减少请求。同一秒内的远端修改可能不被时间戳检测到；需要更严格检查时开启，代价是每轮逐篇下载文档。
- **调试日志**：默认关闭。开启后写入 `.obsidian/feishu-sync/sync.log`，排查后可以关闭。

文档模式首次使用时生成 `.obsidian/feishu-sync/rules.json`。可以在设置中打开它，调整每条规则的 `enabled`；文件内含规则说明。加载时会补齐新增规则，保留已有开关。规则只作用于同步转换，不会为了上传而直接重写本地原稿。

默认公式规则区分两个平台：行内公式 `$x + y$` 清理紧贴定界符的空白，保留公式中间空格；块级公式 `$$…$$` 保留内部空格和换行。上行转换为飞书原生公式，下行恢复 Obsidian 公式语法。代码块、代码片段等不会按公式改写。原稿格式提示 `source-format-diagnostics` **默认关闭**。

规则变化后，预览中会出现需要刷新排版的文档；远端已有新改动时先处理改动。预览后再次更改规则、目标或映射会使旧计划失效，需要重新预览。详细公式约定见 [转换验证记录](docs/math-roundtrip-2026-09-27.md)。

## 冲突与使用边界

两边都修改同一篇且内容不一致时，不自动合并或覆盖：远端取回内容另存到 `.obsidian/feishu-sync/conflicts/`，报告显示副本路径。该目录隐藏在 Obsidian 文件列表之外，可通过系统文件管理器查看；文档模式副本保留飞书取回形态，可能含原生标签，适合对照，不能保证直接作为最终 Markdown 使用。相同冲突不会反复生成副本。

手动对照双方内容，完成合并后再同步。不要用“清空同步状态”来解决内容冲突；清空会丢失基线，只能重新按首次对接判断。

当前还需注意：

- 文档模式以整篇内容更新，不提供实时协同或服务器事务锁；执行前复核可拦截预览后的改动，仍应避免两端同时持续编辑同一篇。
- 文件或文件夹重命名不是跨平台移动操作，可能表现为旧路径删除提示及新路径创建。批量改名后先预览，尤其不要直接确认批量删除。
- 镜像目录会创建用于组织层级的空页面；文档模式将未映射且含子页面的远端页面视为目录，其自身正文不导入。建议使用专用同步区域。
- 扁平模式使用分隔符编码路径；若本地名字本身包含该分隔符，会拒绝同步，避免歧义。优先使用镜像目录模式。
- 文件镜像模式跳过零字节笔记；文档模式允许空正文。附件不是全仓库镜像，仅处理文档中引用的图片，单张图片上限为插件设置的 20 MiB。
- Obsidian 双链、块引用、嵌入笔记、插件语法及飞书独有富文本结构不能保证功能等价；飞书格式化也可能改变列表或段落空白。文档模式不承诺源码无损。
- 网络超时后，写请求可能已经在飞书生效；插件不会盲目重试或再次创建副本。先检查飞书，再重新预览。大量内容的创建可能等待飞书异步处理。
- 知识库列表异常、分页异常或目录超过 20 层时会中止，不以不完整列表推断删除。可选择较小的根节点减少扫描范围。

## 排查问题

| 现象 | 检查方法 |
| --- | --- |
| 插件不出现在列表 | 确认目录没有多嵌套一层，三个文件齐全；重启 Obsidian |
| 授权失败 / `20010` | 应用是否已发布，可用范围是否包含当前账号 |
| 授权失败 / `20027` | 插件授权范围是否全部在应用后台开通，新增权限后是否重新发布与授权 |
| 回调错误 / `20029` | 后台登记 URL 与插件设置是否完全一致，包括协议、端口与路径 |
| 连接成功但知识空间列表为空 | 当前身份是否有该空间权限；应用身份还需配置知识库成员或协作者权限 |
| 图片或文档报权限错误 | 检查文档和素材权限、发布状态，以及目标内容的访问权限 |
| 提示需要重新预览 | 预览后设置、规则、映射或正文变化；关闭旧计划，重新运行预览 |
| 授权失效 / refresh token 错误 | 在该设备重新授权，避免不同设备共用同一份 `data.json` |
| 同步失败或长时间等待 | 查看报告的 HTTP 状态、错误码、log_id；开启调试日志定位，勿连续重复创建 |

## 开发与验证

```sh
npm run dev          # 监听源码，生成开发版 main.js
npm run typecheck    # TypeScript 类型检查
npm test             # 转换规则、运行安全与同步场景测试
npm run build        # 生产构建
npm run package      # 全部检查 + 生产构建 + ZIP + 校验值
```

所有自动测试使用固定合成笔记、临时目录与模拟飞书服务，不依赖个人 Work 仓库，也不访问真实飞书账号。临时数据在测试结束后清理。本次维护的修复与验证说明见 [v1 审查记录](docs/review-v1-2026-10-01.md)。历史线上公式验证记录不能替代新版本的真实账号验收。
